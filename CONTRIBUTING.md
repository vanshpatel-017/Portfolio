# Contributing to Portfolio

Thank you for your interest in contributing! This document provides guidelines for contributing to this portfolio project.

## Getting Started

1. **Fork** the repository on GitHub
2. **Clone** your fork locally:
   ```bash
   git clone https://github.com/YOUR_USERNAME/Portfolio.git
   cd Portfolio
   ```
3. **Create** a feature branch:
   ```bash
   git checkout -b feature/your-feature-name
   ```
4. **Make** your changes and test thoroughly
5. **Commit** with clear, descriptive messages
6. **Push** to your fork and create a pull request

## Code Style & Standards

- Use ES6+ syntax and modern JavaScript practices
- Follow React best practices and hooks conventions
- Keep components focused and reusable
- Add comments for complex logic
- Maintain responsive design principles
- Test changes across different screen sizes

## Commit Message Guidelines

Write clear, concise commit messages using this format:
```
type: brief description

- Detailed explanation of changes
- Additional context or reasoning
- Related issues or references
```

Types: `feat`, `fix`, `docs`, `style`, `refactor`, `test`, `chore`

## Pull Request Process

1. **Update** documentation if needed
2. **Test** your changes thoroughly
3. **Provide** screenshots for UI changes
4. **Write** a clear PR description including:
   - What changes were made
   - Why these changes improve the portfolio
   - Any related issues
   - Testing performed

5. **Be responsive** to feedback and code review comments
6. **Keep commits** clean and organized

## Review Criteria

PRs will be evaluated on:
- ✅ Code quality and best practices
- ✅ Alignment with project goals
- ✅ Responsive design implementation
- ✅ Performance impact
- ✅ Documentation updates
- ✅ Clear commit messages

## Questions?

Feel free to:
- Open an issue for bugs or suggestions
- Ask questions in pull request discussions
- Reach out with improvement ideas

## Code of Conduct

- Be respectful and inclusive
- Provide constructive feedback
- Welcome different perspectives
- Focus on the code, not the person
